# World Quiz, Phase 2: Flags. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Flags section alongside the existing Names section. It has three modes:
- **Learn:** a flag grid, plus a one-by-one viewer.
- **Type:** a big flag is shown and you type its country.
- **Map:** a flag is shown and you click its country on the map.

**Architecture:**
- The quiz reducer gets three new modes. Two of them are new target modes that reuse the existing "target + 3 tries" logic.
- The main area of the app is chosen by mode:
  - The flag stage (Learn and Type) replaces the map completely.
  - Flag Map is the map with a floating flag card on top, not the Names side-panel prompt box.
- Flag images are SVGs from the `world-countries` package. The existing snapshot script copies them into `public/flags/`.

**Tech Stack:** unchanged (Vite, React 19, TypeScript, d3, Vitest + Testing Library). **No new dependencies.**

**Spec:** No separate spec doc. The requirements are the section below, taken from the user's request on 2026-11-27.

## Requirements

1. **Flag Type:** show a flag; the user types the country and presses Enter. It is not map-centred, so there is no map on this screen.
2. **Flag Learn**, with two views:
   - a grid of every flag in scope, with names;
   - a one-by-one view. Clicking a flag in the grid opens the one-by-one view on that flag.
3. **Flag Map:** show a flag; the user clicks that country on the map.
4. Flag Map must feel like its own game. The flag is a prominent card over the map, not a small box in the side panel like the Names "Click" prompt.
5. Inherited from phase 1:
   - World or one-continent scope
   - Reset, Give up and Retry missed at any time
   - progress saved in localStorage
   - Enter to confirm typing
   - 3 tries per target

## Decisions I made (check these)

- **D1 Navigation:** a `Names | Flags` switch sits at the top of the side panel.
  - Names keeps Type / Click / Explore.
  - Flags shows Learn / Type / Map.
  - Switching section opens that section's first mode: Names → Type, Flags → Learn.
- **D2 Scope** is shared between sections. Picking Europe in Names keeps Europe in Flags.
- **D3 Flag Type answers:**
  - Any recognised country that is not the target costs a try. This includes countries outside the scope.
  - Unrecognised text costs nothing and shows "Not recognised".
  - The third wrong answer reveals the country and marks it missed.
- **D4 "I don't know" button** in Flag Type and Flag Map. It reveals the country, marks it missed and moves on. It is not added to Names Click.
- **D5 Feedback after a correct or revealed answer** shows a small copy of that flag next to the name ("✓ 🇧🇪 Belgium"). The big flag has already moved on, so this is the only moment you see the answer next to its flag.
- **D6 One-by-one view:**
  - ←/→ keys and Prev/Next buttons step through the flags. Stepping wraps around, and a counter ("12 / 54") shows the position.
  - Esc or "All flags" returns to the grid, with focus on the flag you were viewing.
  - Changing scope returns to the grid.
- **D7 Flag Learn has no progress**, like Explore. Each flag quiz mode keeps its own progress: Flag Type and Flag Map are separate from each other and from Names Type and Click.
- **D8 Panel list:**
  - In flag quiz modes, the panel list shows found and missed countries with a mini flag.
  - In Learn, the list is hidden, because the grid is the list.
- **D9 Flag files** are copied as they are (197 files, 3.8 MB in total, the largest 345 KB) and loaded lazily. They are not minified, because that would need a new dependency.

### Task 2: Reducer and storage for flag modes

**Files:**
- Modify: `src/quiz/reducer.ts`, `src/quiz/storage.ts`
- Test: `src/quiz/reducer.test.ts`, `src/quiz/storage.test.ts` (append)

**Interfaces:**
- Produces, in `reducer.ts`:
  - `type Mode = 'explore' | 'type' | 'click' | 'flagLearn' | 'flagType' | 'flagMap'`
  - `type QuizMode = 'type' | 'click' | 'flagType' | 'flagMap'`
  - `isQuizMode(m: Mode): m is QuizMode`
  - `type Section = 'names' | 'flags'` and `sectionOf(m: Mode): Section`. `flagLearn`, `flagType` and `flagMap` → `'flags'`; the rest → `'names'`.
  - `Feedback` gains `{ kind: 'wrong-name'; id: string; triesLeft: number }`.
  - `QuizAction` gains `{ type: 'reveal' }`.
  - `QuizState.progress: Record<QuizMode, Progress>` now has 4 keys. `initialState` fills any missing key with empty progress.
- Behaviour:
  - **Target modes** are `click`, `flagType` and `flagMap`. `retarget` picks a target only in these modes.
  - **`setMode`:** setting the same mode is a no-op, unless the mode is a target mode whose target is `null`.
  - **`typed`:** in `type`, behaviour is unchanged. In `flagType` with target T:
    - `id === T` → found, feedback `correct`, retarget.
    - Any other id → a wrong try, using the same counting as `clicked` (feedback `wrong-name` with `triesLeft`). On the 3rd wrong try T is marked missed, feedback is `revealed`, and the reducer retargets.
    - All other modes → no-op.
    - Factor the shared wrong-try path into one helper used by both `typed` and `clicked`.
  - **`clicked`:** runs in `click` and `flagMap`, against `progress[s.mode]`. Wrong clicks still give `wrong-click`.
  - **`reveal`:** in a target mode with a target, marks the target missed, gives feedback `revealed` and retargets. Otherwise it is a no-op (returns the same object).
  - **`giveUp`, `reset`, `retryMissed`, `statusOf`, `pendingIn`:** every place that checks `mode === 'explore'` now checks `!isQuizMode(mode)`. As a result, `flagLearn` behaves like `explore`.
- Produces, in `storage.ts`:
  - `MODES` lists all 6 modes.
  - `type` and `click` progress are required, as now.
  - `flagType` and `flagMap`:
    - missing → empty progress;
    - present but invalid → `loadSaved()` returns `null`.
